# 2026-09-19 — 일반 근접 적 행동 AI (비헤이비어 트리)

[melee-enemy-ai-spec.html](melee-enemy-ai-spec.html)의 설계를 코드로 옮겼다.
임시 더미였던 `EnemyBrain`(제자리에서 3초마다 공격)을 대체하는 **의사결정 계층**이다.

## 배경

- 브랜치 `develop4`. [2026-09-02](2026-09-02.md)에서 "몸" 구조(Actor/Locomotion/Fighter/Health/StateMachine)를
  끝내고 미뤄뒀던 **적 AI 판단 로직**이 이번 범위.
- 설계서가 먼저 있었고, 그 8개 잎 노드를 **하나씩 만들고 단독 테스트한 뒤 마지막에 트리로 조립**하는 순서로 진행.
- 작업 시작 시점에 `.cs` 없이 `.meta`만 남은 이전 시도의 잔재가 있었다(`BTNode` `MeleeEnemyContext`
  `MoveToTargetNode` 등 6개 + 값이 채워진 `MeleeEnemyAIData.asset`). **전부 지우고 새로 시작**.

## 원칙

> **AI는 "무엇을 할지"만 고른다.** 공격 판정·넉백·피격 처리·애니메이션은 전부 기존 코드 그대로.

노드는 `CharacterIntent`를 채울 뿐이고, 그 뒤는 `PlayerInput`이 만든 의도와 한 글자도 다르지 않게 흘러간다.
덕분에 공격 잠금·피격 경직·상태 전이가 전부 공짜로 따라온다.

## 결정 (작업 전 질문한 것)

| 갈래 | 선택 | 이유 |
|---|---|---|
| 기존 코어 수정 범위 | **추가만 허용** (3곳) | 속도 배율·피격 통보·점프 벡터가 없으면 설계서를 구현할 수 없었음 |
| 점프 계열 순서 | 지상 6개 먼저, 점프는 마지막 | 적에게 `JumpStart`/`JumpLand` 클립이 없어 블로킹 |
| 이전 시도 잔재 | 전부 삭제 후 새로 | GUID 보존보다 설계 자유도 우선 |

## 기존 코드에 추가한 것 (전부 additive, 직렬화 필드 변경 없음)

| 파일 | 추가 | 왜 필요했나 |
|---|---|---|
| `CharacterIntent` | `MoveSpeedScale` | `SetMoveInput`이 방향만 쓰고 크기를 버려서, 같은 방향을 다른 속도로 갈 방법이 없었음 |
| `Actor` | `fighter.MoveSpeedMultiplier * intentSpeedScale` | Actor가 매 프레임 `MoveSpeedMultiplier`를 덮어써서 AI가 직접 못 건드림 |
| `Locomotion` | `MoveSpeed` / `BoundaryRadius` 읽기 프로퍼티 | 절대 속도(6.0/초)를 배율로 환산 / 벽까지 거리 계산 |
| `Health` | `event Action<HitData> OnHitTaken` | 상태 폴링으로는 **넉백 0인 공격에 맞은 것을 놓친다** |

`MoveSpeedScale`은 `CharacterIntent.None`이 `default`라 0이 기본값일 수밖에 없다 →
**0을 "지정 없음(=1)"으로 읽는다.**

## 만든 것

### 트리 인프라 — `Assets/Script/Enemy/AI/`

| 파일 | 역할 |
|---|---|
| `BTNode` | `Tick`이 `OnEnter`/`OnExit`를 자동으로 끼워 넣는다. `Abort`로 밖에서 끊김 |
| `MeleeEnemyContext` | 노드 공용 작업판. xz 평면 계산 · 트리거 범위 · 공격권 중개 · 피격 신호 |
| `SequenceNode` | 순서대로, 하나라도 실패하면 중단 |
| `WeightedRandomNode` | 가중치 랜덤 |
| `AttackSlotScopeNode` | 감싼 묶음이 도는 동안 공격권 유지 + **반납 보장** |
| `ActionSelectorNode` | 거리·슬롯으로 상황 판정 → 그 상황의 가중치 표에서 뽑기 |
| `ConditionNode` | 조건만 재고 Success/Failure. Sequence가 Failure에서 멈추는 성질로 분기를 만든다 |
| `IMeleeEnemyAIDebugInfo` | 기즈모가 AI/테스터 어느 쪽에 붙어도 동작하게 |

노드는 MonoBehaviour가 아닌 **평범한 C# 객체**. 씬에 얹을 것이 없어 단독 테스트가 쉽고 조립은 생성자 호출뿐.
대신 **상태를 필드로 들고 있어 인스턴스를 공유하면 안 된다** (원거리용/근거리용 근접 묶음을 따로 만드는 이유).

### 잎 노드 — `Assets/Script/Enemy/AI/Nodes/`

| 설계서 | 파일 | 비고 |
|---|---|---|
| ① 공격 접근 | `MoveToTargetNode` (approach 프로필) | |
| ② 근접 공격 | `MeleeAttackNode` | 커밋형. 중간 취소 없음 |
| ③ 점프대쉬 | **미구현** | 점프 클립 대기 |
| ④ 공격 후 대기 | `PostAttackWaitNode` | |
| ⑤ 공격 후 느린 이동 | `MoveToTargetNode` (slowStep 프로필) | |
| ⑥ 자리 재정렬 | `MoveToTargetNode` (reposition 프로필) | 원 둘레의 랜덤 지점. 가는 길에 플레이어가 있으면 비켜 돌기 |
| ⑦ 피격 경직 | `HitStunNode` | 기다리기만 함. 거쳐 간 상태로 **넘어졌는지** 판별 |
| ⑧ 피격 후 이탈 | `MoveToTargetNode` (escape 프로필) | **점프 → 지상 이동으로 변경** |

**이동 노드는 하나뿐이다.** 네 행동의 차이가 전부 `MoveProfile` 값의 차이로만 표현된다 —
목표를 어디로 잡나(`MoveGoal`) · 언제 다시 보나(`MoveTracking`) · 어떻게 가나(`MovePath`).

### 조립된 트리 — `MeleeEnemyAI`

```
루트
├─ 피격 신호? ──→ Sequence[ ⑦ 경직 → 넘어졌나? → ⑧ 이탈 ] ──→ 루트로 (완전 랜덤 재선택)
└─ 전투 루프 ──→ 행동 선택
                  ├─ 슬롯 막힘  → 대기 35 : 느린이동 30 : 재정렬 35
                  ├─ 원거리(4↑) → 근접 50 : 재정렬 25   [점프대쉬 25 자리 비어 있음]
                  └─ 근거리      → 근접 65 : 재정렬 35

   근접 묶음 = Sequence[ 공격권점유{ Sequence[①접근, ②공격] }, ④⑤ 공격 후 2택 ]
```

피격은 **트리 안의 조건이 아니라 바깥에서 끼어드는 신호**다. `Health.OnHitTaken` → `context.NotifyHit()` →
루트가 돌던 가지를 `Abort`하고 피격 분기로 갈아탄다.

## 경로 곡선 — 가장 오래 붙잡은 것

설계서 ①의 "ㄱ자 급곡선"이 원하는 모양으로 안 나와서 네 번 고쳤다. 순서대로 무엇이 틀렸는지가 기록할 가치가 있다.

| 증상 | 원인 | 고친 것 |
|---|---|---|
| **직각으로 꺾임** | `zWeight = clamp(dz/0.3)` — 0.3 밖이면 x를 완전히 죽임. 섞일 구간이 0.05초뿐 | 선회 속도(도/초) 제한 도입 + 기준 거리 0.3 → 1.5 |
| **S자로 출렁임** | z 목표선을 지나친 뒤 `abs(dz)`가 다시 커져 x 억제가 **다시 켜짐** → 되돌아감 | 억제량을 단조 감소로 + 히스테리시스 |
| **여전히 출렁임** | 선회 제한 때문에 **목표선에 도착한 뒤 꺾기 시작하면 이미 늦다** | 꺾기 시작 거리를 **선회 반지름에서 자동 계산** + 마지막 프레임 z 성분 하드 클램프 |
| **끝에서 갈고리처럼 꼬임** | `z성분 = zTerm × (1−w)` — 목표 근처에서 두 항이 동시에 0으로 가 **z가 이중 억제**됨. z 오차가 0.5일 때 진행 방향이 이미 88°(거의 순수 x)라 z를 x 이동량의 3.7%씩밖에 못 줄임 → x가 다 떨어진 마지막에 몰아서 처리 | `(1−w)`를 빼고 z를 dz에 **비례**하게만. 오차가 지수적으로 감소(길이상수 = 기준 거리) |

최종 공식 (`ResolveGradualTurn`):
```
w = min(1, s² / dz²)          // x 비중. dz = s 에서 정확히 45도
dir = (clamp(dx/s) × w,  0,  clamp(dz/s))
```

> **기하 메모:** 반지름 r인 호로 90도 돌면 정확히 r만큼 전진한다. 그래서 목표선보다 **r 앞에서**
> 꺾기 시작해야 넘어가지 않고 접선으로 안착한다(= J자). 이 r이 `속도 ÷ 선회속도(rad)`다.

중간에 "임계값으로 직선→곡선을 딱 나누지 말고 기울기가 점차 늘어나게" 요청을 받아
**경계 자체를 없앴다**. 예전 단계 전환 방식은 `ㄱ자 꺾임 방식` 드롭다운으로 남겨 뒀다(롤백용).

## 실제 겪은 버그

### 1. Tooltip 문자열에 실제 줄바꿈이 들어가 컴파일 에러
`CS1003: Syntax error, ',' expected`. 스크립트로 파일을 고치면서 `\n` 이스케이프가 그대로 개행이 돼
C# 문자열 리터럴이 끊겼다. 이후 전체 `.cs`를 훑어 "주석 제외 후 따옴표가 홀수인 줄"을 검사하는 루틴을 매번 돌렸다.

### 2. `Random`이 모호 — `CS0104`
`WeightedRandomNode`가 `Func<float>` 때문에 `using System;`을 넣자
`System.Random`과 `UnityEngine.Random`이 충돌. `UnityEngine.Random.value`로 명시.

### 3. "Success인데 공격을 안 한다"
로그가 `Success … 공격권 보유`로 찍히는데 아무 일도 없었다. **원인은 로그 문구였다** —
`공격권 보유`는 어느 노드를 돌리든 찍히고, `AttackSlots`가 없으면 "항상 비어 있음" 규칙 때문에 "보유"로 나온다.
실제로는 `실행할 노드`가 여전히 **① 공격 접근**이었다(새 항목을 enum 맨 뒤에 붙여서 저장된 선택값이 그대로였음).

> 교훈: 디버그 로그가 **스스로를 구분하지 못하면** 없느니만 못하다.
> 이후 `Fighter 공격 시작/종료`를 노드와 무관하게 직접 찍고, 슬롯 표기를 정직하게 바꿨다.

### 4. 피격 경직 시간이 클립과 무관했다
`Stun`이 **물리 파생 상태**라 `IsGroundSliding`이 꺼지는 순간이 곧 경직 끝이었다.
`밀치는 힘 6 ÷ 감속 30 = 0.2초`인데 `Stun.anim`은 0.4167초 → **클립이 절반만 재생되고 잘렸다.**

→ `Stun`을 **고정(sticky) 상태**로 옮기고 `Stun` 클립 길이만큼 유지하게 바꿨다.
`AttackData.ResolveDuration()`과 같은 규칙(클립 길이 또는 직접 지정)이고, `Attack`처럼 타이머로 자력 종료하므로 워치독 제외.
**경직이 끝나면 남은 미끄러짐도 같이 끊는다** — 안 그러면 "움직일 수는 있는데 아직 밀려나는 중"인 구간이 생긴다.

> 처음엔 Animation Event(`OnHitStunEndFrame`)로 구현했다가, "굳이 이벤트를 심어야 하나"는 지적을 받고
> 컨트롤러에서 클립 길이를 직접 읽는 방식으로 교체했다. **State 이름 == 클립 이름**이 이미 불변식이라 가능.

## 계획(설계서) 대비 바꾼 것

| 설계서 | 실제 | 이유 |
|---|---|---|
| ⑧ 이탈 **점프** | 지상 이탈 이동 | 적에게 점프 클립이 없음. 이동 프로필 하나로 표현되고 클립이 필요 없음 |
| 피격 뒤 **항상** 이탈 | **넘어졌다 일어날 때만** 이탈 | 가벼운 지상 경직까지 매번 물러나면 한 대 칠 때마다 적이 도망쳐 전투가 늘어지고, 큰 공격으로 넘어뜨렸을 때의 "거리가 벌어진다"는 신호도 같이 묻힌다 |
| 슬롯 검사를 근거리에서만 (그림 6) | **거리보다 먼저** 검사 | 8장 본문이 거리와 무관하게 "공격 후보를 뺀다"고 명시. 자리도 없는데 원거리에서 접근부터 하면 다 가서야 못 때린다는 걸 알게 됨 |
| ⑥ 재정렬이 "반대편"으로 | 플레이어 주변 **원 둘레의 랜덤 지점** | 매번 정확히 반대편이면 움직임이 읽힌다 |
| ⑥ 항상 반원 | **가는 길에 플레이어가 있을 때만** 비켜 돌기 | 원호가 있는 이유가 "플레이어를 뚫고 가지 않으려고"이므로, 길이 비어 있으면 도는 건 돌아가는 길일 뿐이다. 목적지까지의 직선과 플레이어 사이 최단거리로 판정 |
| 좌/우 슬롯을 각각 예약 | 층별 **동시 공격 수**만 셈 | "슬롯은 공격권이지 고정된 자리가 아니다"를 따르면 좌우를 예약해도 지켜지지 않음 |
| `z 우선 임계값` 0.3 | 1.5 (의미도 "45도가 되는 거리"로 변경) | 0.3은 섞일 구간이 없어 무조건 직각 |
| 10장에 없던 값 2개 추가 | `느린 이동 전진 전환 거리` 3.0 / `공격 시작 대기 한계` 1.0 | 8장 "가까우면 뒤로, 멀면 앞으로"의 경계 / 안전장치 |
| `이탈 점프 거리`·`체공 시간` | **삭제** | 이탈 프로필의 `이동 속도`(3.5÷0.4=8.75) + `이동 거리 제한`(3.5)이 대신함 |

## 검증 체크리스트

단독 테스트는 `MeleeEnemyNodeTester`에서 노드를 하나 골라 무한 반복.

- [x] ① 접근 — z가 다르면 ㄱ자, 같으면 직진. 0.15초 주기로 살짝 뒤처져 따라옴
- [x] ① 접근 — 플레이어가 지나쳐 좌우가 뒤집히면 **선회 제한을 건너뛰고** 즉시 새 경로
- [x] ② 공격 — 제자리에서 반복. 거리와 무관(그게 정상). 맞으면 `Failure`로 끊김
- [x] ④⑤ 2택 — 50:50으로 번갈아. 가중치를 100:0으로 바꾸면 즉시 반영
- [x] ⑤ 느린 이동 — 시작 후 플레이어가 움직여도 **따라오지 않음**(스냅샷)
- [x] ⑦ 경직 — 약하게 맞으면 슬라이드 동안, 세게 맞으면 다운·기상까지 지난 뒤 Success
- [ ] ⑥ 재정렬 — 목적지까지의 직선에 플레이어가 **걸리면** 비켜 돌고, **안 걸리면** 직선
- [ ] ⑥ 재정렬 — 추적을 스냅샷으로 두고 플레이어를 움직여도 **찍은 점 그대로** 가는지
- [ ] ⑧ 이탈 — 벽을 등지고 몰렸을 때 옆으로 빠지는지
- [ ] 피격 분기 — **가벼운 공격**엔 경직만 하고 제자리, **띄우는 공격**에만 넘어졌다 일어나서 이탈
- [ ] 통합 — 슬롯 0으로 막았을 때 공격 후보가 빠지는지
- [ ] 경직 0.42초로 늘어난 뒤의 전투 템포 (플레이어도 같이 적용됨)

| **③ 점프대쉬** | 적 `JumpStart`/`JumpLand` 클립 + 애니메이터 스테이트 + 이벤트가 있어야 함. `Locomotion.PrepareJump`가 x축만 받고 속도도 `moveSpeed` 고정이라 **Vector3 오버로드도 같이 필요** |
| 원거리 + 슬롯 막힘 | 지금은 비공격 표로 떨어진다. 점프대쉬가 붙으면 **점프대쉬·재정렬만 남는 별도 상황**으로 나눠야 함 |
| `EnemyBrain.cs` | `MeleeEnemyAI`로 대체됐지만 파일은 남겨둠. 지울지 판단 필요 |
| 수치 튜닝 | 설계서 10장은 전부 임시값. 특히 가중치와 선회 속도 |

## 유지할 것

| 항목 | 이유 |
|---|---|
| **이동 노드는 하나** | 네 행동의 차이가 전부 `MoveProfile` 값. 변형 적은 이 에셋만 새로 만들어 찍어낸다 |
| **가중치는 `Func<float>`로 받는다** | 생성자에서 숫자를 읽어두면 플레이 중 인스펙터 변경이 반영 안 됨 |
| **상황 판정은 들어올 때 한 번만** | 매 프레임 다시 판정하면 거리 경계에서 행동이 깜빡이며 아무것도 못 함 |
| **목표와 공전 중심은 `CaptureGoal`로 함께 잡는다** | 따로 갱신하면 스냅샷으로 찍은 점은 그대로인데 궤도만 플레이어를 따라 끌려다닌다 (실제로 겪은 버그) |
| **랜덤 목적지 각도도 시작할 때 한 번만** | 실시간 추적은 목표를 매 프레임 다시 계산한다. 거기서 뽑으면 목적지가 원 위를 튀어 다녀 영영 도착 못 함 |
| **공격권 반납은 `AttackSlotScopeNode`가 보장** | 새면 그 자리가 영영 잠겨 다른 적이 영원히 못 때림 |
| **공격 후 행동은 공격권 껍데기 밖** | 숨 고르는 동안 자리를 붙들고 있으면 안 됨 |
| **이탈은 넘어졌을 때만** | 매번 물러나면 전투가 늘어지고, 넘어뜨렸을 때의 리듬 변화가 묻힌다 |
| `HitStunNode.WasKnockedDown`을 **매 프레임 갱신** | 첫 프레임만 보면, 경직 도중 다시 맞아 그때 떠오르는 경우를 놓친다 |
| **기즈모는 직선이 아니라 예측 곡선** | J자인지 S자인지는 직선으로는 전혀 안 보여 수치를 맞출 수가 없음 |
| `MeleeEnemyNodeTester` | 노드를 하나만 떼어 보는 도구. 변형 적을 만들 때 다시 필요 |
| 테스터 enum 새 항목은 **맨 뒤에** | 순서를 바꾸면 씬에 저장된 선택값이 엉뚱한 항목을 가리킴 |
| `ㄱ자 꺾임 방식` = 단계 전환 | 예전 방식 롤백용. 코드를 되돌리지 않고 인스펙터로 A/B 비교 가능 |
