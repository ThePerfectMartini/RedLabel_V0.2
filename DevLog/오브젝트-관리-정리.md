# 오브젝트가 어떻게 관리되는가

캐릭터(플레이어 · 적 · 훈련 더미) 오브젝트 하나가 매 프레임 어떤 순서로,
어떤 컴포넌트를 거쳐 움직이고 때리고 맞는지 정리한 글.
"함수 시그니처"는 [프로젝트-사전.md](프로젝트-사전.md), "만드는 법"은
[프로젝트-설명서.html](프로젝트-설명서.html)에 있고, 이 문서는 **로직이 어떻게 나뉘어 있는지**만 다룬다.

작성 기준: 적 AI 1차 완성 (2026-09-09). 적 AI 상세는 부록 A + [프로젝트-사전.md §7.5](프로젝트-사전.md).

---

## 0. 큰 원칙

**"무엇을 할지"를 정하는 쪽과 "몸"이 완전히 분리돼 있다.**

- 판단은 `IIntentSource` 구현체가 한다 — 플레이어는 `PlayerInput`(키 입력), 적은 `EnemyBrain`(AI).
  둘 다 매 프레임 `CharacterIntent` 값 하나를 채워서 넘길 뿐이다.
- 몸은 `Locomotion`(이동) · `Fighter`(공격) · `Health`(피격) · `CharacterStateMachine`(상태·애니메이션)
  네 컴포넌트로 나뉘고, 그 위에 선택적으로 `Dodger`(회피) · `Parrier`(패링)가 붙는다.
- `Actor`가 이 사이를 조율한다. **`Actor`만 `Update()`를 가진다.** 나머지 몸 컴포넌트는 자기 `Update()`가
  없고, `Actor`가 정해진 순서로 메서드를 불러줄 때만 움직인다.

그래서 조종 주체가 사람이든 AI든 몸 쪽 코드는 한 글자도 안 바뀐다.
`IIntentSource`가 아예 없으면 `Actor`는 `CharacterIntent.None`으로 돌고, 결과적으로 제자리에 서서
맞아주기만 하는 **훈련 더미**가 된다.

```
IIntentSource (PlayerInput / EnemyBrain)
      │  GetIntent(dt) → CharacterIntent
      ▼
   ┌───────┐   유일한 Update. 프레임 순서를 한 곳에 고정.
   │ Actor │
   └───────┘
      │ 정해진 순서로 호출
      ├─▶ Dodger.TryDodge / Parrier.TryParry      (방어가 공격보다 먼저)
      ├─▶ Fighter.TryAttack
      ├─▶ Locomotion.SetFacing / SetMoveInput / Tick
      └─▶ CharacterStateMachine.Enter* / Evaluate

  Fighter  ─▶ Locomotion (돌진·슬라이드 정리) + StateMachine (공격 상태·클립)
  Health   ─▶ Fighter (CancelAttack) + Locomotion (ApplyKnockback) + StateMachine (Interrupt)
  Dodger   ─▶ Fighter (CancelAttack) + Locomotion (대시) + StateMachine (Dodge 상태)
  Parrier  ─▶ 공격자의 Health.OnHit (데미지 0 → 스턴) + StateMachine (Parry 상태)

  [Visual 자식] AnimationEventRelay ─▶ Fighter / CharacterStateMachine  (클립 이벤트 중계)
  다른 Actor의 Fighter ─▶ 이 Actor의 Health.OnHit  (오브젝트를 건너뛴 유일한 호출, IHittable)
```

`Locomotion`은 이 그래프의 종점이다 — 남에게 시키기만 받고, 아무도 부르지 않는다
(애니메이션 이벤트로 들어오는 `Jump()` 한 건 예외).

## 1. 한 프레임의 흐름 (`Actor.Update`)

순서 자체가 규칙이다. 특히 **방향은 공격이 시작되기 전, 이동은 시작된 후**에 잠금을 판정한다.

| # | 하는 일 | 이유 |
|---|---|---|
| ① | `intentSource.GetIntent(dt)` 로 이번 프레임 의도 획득 | 없으면 `CharacterIntent.None` |
| ② | 공격 시작 **전** 잠금으로 `locomotion.SetFacing(intent.FacingDirection)` | "→ + X"를 한 프레임에 눌러도 오른쪽으로 공격 나가게 |
| ③ | `intent.WantsDodge` → `dodger.TryDodge()` / `intent.WantsParry` → `parrier.TryParry()` | 방어가 공격보다 먼저 — 같은 프레임에 같이 눌리면 방어 우선 |
| ④ | `intent.AttackToStart != null` → `fighter.TryAttack(...)` | 방금 정한 방향으로 공격 |
| ⑤ | `intent.WantsJump` && 지상 && `CanAct` → `locomotion.PrepareJump()` + `stateMachine.EnterJumpStart()` | 아직 안 뜸. 준비 클립의 이벤트가 실제로 띄운다 |
| ⑥ | 공격·점프까지 반영해 다시 계산한 잠금으로 `locomotion.SetMoveInput(intent.MoveInput)` + `MoveSpeedMultiplier` 갱신 | 이동 잠금은 "이번 프레임에 시작된 동작"까지 봐야 정확 |
| ⑦ | 착지 엣지 감지용으로 `LaunchedByJump` / `IsKnockedBackAirborne` 스냅샷 | Tick 후 값과 비교하려고 |
| ⑧ | `locomotion.Tick(dt)` — 실제 위치 확정 | 이 프레임의 모든 입력이 여기서 한 번에 적분됨 |
| ⑨ | 점프 착지 엣지 → `EnterJumpLand()` / 넉백 착지 엣지 → `EnterLanded()` | 공중→지상으로 바뀐 그 프레임에만 |
| ⑩ | `fighter.Tick(dt)` → `dodger.Tick(dt)` → `parrier.Tick(dt)` → `stateMachine.Evaluate()` | 각자 타이머 소진 체크 → 마지막에 상태 재판정 |

**각 몸 컴포넌트에 `Update()`가 없는 이유:** 상태 변화는 (a) 이 `Update`의 명시적 호출,
(b) `AnimationEventRelay`(Animator가 비동기 호출), (c) 다른 `Actor`의 공격(직접 호출) 셋으로만 일어난다.
어느 것도 "이번 프레임에 다른 컴포넌트의 `Update`가 먼저 돌았는지"에 기대지 않으므로
`[DefaultExecutionOrder]` 같은 실행 순서 지정이 필요 없다.

## 2. 이동 — `Locomotion`

오브젝트의 **모든 위치 이동**은 `Locomotion`을 통한다. Rigidbody를 쓰지 않고 중력·점프·넉백·바운스·
맵 경계 클램프를 전부 손으로 계산해서 `transform.position`에 직접 반영한다.

### 이동은 세 갈래

| 갈래 | 진입 메서드 | 특징 |
|---|---|---|
| **직접 입력 이동** (플레이어 상하좌우, 적 추격) | `SetMoveInput(Vector2)` | 지상에서만. 8방향 스냅 여부는 `use8DirectionSnap`(플레이어 켬 / AI 끔). 속도 = `moveSpeed × MoveSpeedMultiplier` |
| **동작에 수반된 이동** (점프, 돌진 공격, 회피 대시) | `PrepareJump`→`Jump` / `ApplyKnockback(v, decel)` | 공격·회피가 "그 동작의 일부"로 부여. 돌진·대시는 `ApplyKnockback`의 y=0 경로(= 그라운드 슬라이드)를 재사용 |
| **피격·이벤트로 밀리는 이동** (넉백, 패링당한 스턴) | `ApplyKnockback(v, decel)` | 수직 속도가 임계값 초과면 공중으로 띄우고(바운스 대상), 이하이고 지상이면 안 뜨고 그라운드 슬라이드 |

세 갈래가 전부 같은 `velocity` 하나에 모이고, `Tick(dt)` 한 번이 **슬라이드 감속 → 중력 → 위치 적분
→ 바닥 충돌/바운스 → 맵 경계 클램프** 순서로 마무리한다.

### 방향(Facing)은 이동과 분리

`SetFacing`은 x 성분만 보고 좌/우를 정하며 **지상에서만** 반영한다. 이동 방향과 바라보는 방향이
다를 수 있어서(뒷걸음질 치며 상대를 계속 바라봄) `MoveInput`과 별도 필드다.
스프라이트가 좌우로만 뒤집히므로 `FacingDir`은 항상 `right` 또는 `left`, 공격 판정도 이 방향으로 나간다.

### 공중에 뜬 "이유"를 하나로 관리 — `AirborneOrigin`

`None` / `Jump` / `Knockback` 셋 중 하나. 공중 진입점이 `Jump()`와 `ApplyKnockback()` 둘뿐이라
출처가 항상 확정된다. 착지하면 `None`으로 소멸한다.

- `Jump` — 바운스 없이 착지, 착지하면 착지 경직으로
- `Knockback` — 바닥/벽에서 바운스, 착지하면 쓰러짐(`Landed`)

> 예전엔 `isKnockedBack` / `LaunchedByJump` 두 bool이었는데 `(true, true)` 같은 무효 조합이
> 표현 가능했다. enum으로 합쳐서 소멸.

### 준비물

같은 오브젝트에 Collider 하나(타입 무관 — 크기로 바닥 높이·벽 반경 자동 계산),
씬에 `MapBounds` 하나(없어도 넓은 기본 경계), `Resources/`에 `GlobalPhysicsData`(전역 중력).

## 3. 공격 — `Fighter` + `AttackData`

근접 공격. **공격을 실행하는 오브젝트의 위치를 기준으로 지정한 위치에서 다른 오브젝트를 검사**하고,
찾은 오브젝트의 `IHittable.OnHit`을 부른다.

### 입력 시점과 판정 시점이 분리돼 있다

| 시점 | 메서드 | 누가 부름 |
|---|---|---|
| **입력** — "공격하고 싶다" | `Fighter.TryAttack(AttackData)` | `Actor` (`intent.AttackToStart`) |
| **판정** — "지금 때린다" | `Fighter.OnAttackHitFrame()` | 공격 클립의 Animation Event (`AnimationEventRelay` 경유) |

판정은 클립의 타격 프레임에 그 **시점의 위치·방향**으로 수행된다.
`Physics.OverlapSphere(위치 + 방향 × 사거리, 반경, 대상 레이어)` → 각 콜라이더에서
`GetComponentInParent<IHittable>()` → `HitData` 만들어 `OnHit`.
한 스캔에서 같은 대상을 `HashSet`으로 중복 제거한다(대상이 콜라이더 여러 개일 때 대비).

### "지금 공격 중인가"의 권한은 상태머신이 갖는다

`Fighter.IsAttacking`은 별도 플래그가 아니라 `stateMachine.CurrentState == Attack`이다.
`Fighter`는 **어떤 공격 데이터인지**와 **언제 다음 단계로 넘길지**만 관리한다.

- **쿨타임 게이트** — `cooldownUntil` 전에는 새 콤보 시작 불가
- **콤보 체인** — 공격 지속시간 안에 같은 공격이 다시 들어오면 `comboBuffered`, 클립이 끝날 때 `nextAttack`으로 전환
- **캔슬 윈도우** — 다른 공격은 그 공격이 `canCancelOtherAttacks`이고 현재 공격이 타격 프레임을 지난(`hasFiredHitFrame`) 뒤에만 즉시 캔슬 가능

### 공격의 이동 방식은 `AttackData` 하위 타입이 정한다

`AttackData`는 abstract ScriptableObject. 하위 타입별로 에셋을 만든다.

| 타입 | 공격 중 몸 | 오버라이드 |
|---|---|---|
| `LockedAttackData` | 제자리 고정 | `AllowsPlayerMovement => false` |
| `ImpulseAttackData` | 지정 방향으로 강제 돌진 | `ApplySelfMovement`에서 `locomotion.ApplyKnockback` |
| `AllowInputAttackData` | 이동 가능(속도 배율) | `MoveSpeedMultiplier` |

`Fighter`는 타입을 분기하지 않고 `data.AllowsPlayerMovement` / `data.MoveSpeedMultiplier` /
`data.ApplySelfMovement(...)`만 부른다. `Actor`는 그 결과를 이동 잠금 계산에 쓴다.

### 피격당하면 뒷정리만

`Health`가 `Fighter.CancelAttack()`을 부른다 — 타이머·콤보 예약·슬라이드를 정리할 뿐,
**상태 전이는 하지 않는다**(그건 `CharacterStateMachine.Interrupt`가 담당).

## 4. 피격 — `Health`

대상 오브젝트가 공격에 맞으면 `Health.OnHit(HitData)`가 실행된다. `Health`가 `IHittable` 구현체다.

### `OnHit`의 판정 순서 (앞에서 걸리면 그 프레임 피격 전체를 무시)

1. `dead`면 무시
2. **패링 판정 창** 중이면 → `Parrier.NotifyParried(공격자)` 로 넘기고 return
   (Parrier가 성공 연출로 전환하고, 공격자의 `OnHit`을 데미지 0으로 다시 불러 스턴시킨다)
3. **회피 무적 프레임** 중이면 → `Dodger.NotifyDodgedAttack(공격자)` 알리고 return (데미지·넉백·경직 전부 무시)
4. 통과 → 데미지 적용 → `fighter.CancelAttack()` → 넉백 → `stateMachine.Interrupt()` → 체력 0 이하면 `OnDeath`

### 넉백은 지상용·공중용을 둘 다 받아서 대상이 고른다

공격자(`Fighter`)는 맞은 대상이 지금 떠 있는지 알 수 없다 — 그건 대상만 아는 정보다.
그래서 `HitData`에 `KnockbackVelocity`(지상)와 `AirborneKnockbackVelocity`(공중)를 둘 다 실어 보내고,
`Health.OnHit`이 `hit.ResolveKnockbackVelocity(!locomotion.IsGrounded)`로 골라
`locomotion.ApplyKnockback`에 넘긴다. 공중 저글링에서 지상 첫 타와 공중 추가타를 다르게 조절할 수 있다.

### 상태 끊기는 분기하지 않는다

`stateMachine.Interrupt()`는 지금이 어떤 고정 상태든 **무조건** 물리 파생 상태로 되돌린다.

> 예전엔 피격 쪽이 "점프 중이면 이 플래그, 공격 중이면 저 플래그"를 하나씩 껐고,
> 하나라도 빠뜨리면 그 동작의 Animation Event가 영영 안 와서 이동이 영구히 잠겼다.
> 분기를 없앤 게 이 구조의 핵심.

### 사망

`Health`는 `OnDeath` 이벤트만 쏜다. 소멸·연출은 이 이벤트를 구독하는 별도 컴포넌트 몫
(현재 스켈레톤 범위엔 없음 — 죽은 캐릭터는 `dead` 플래그로 더 이상 안 맞고 제자리에 남는다).

## 5. 방어 — `Dodger`(회피) · `Parrier`(패링)

둘 다 `Fighter`가 공격을 다루는 것과 **같은 틀**이다: 입력은 `Actor`가 `TryDodge` / `TryParry`로 넘기고,
sticky 상태(`Dodge` / `Parry` / `ParrySuccess`)의 권한은 `CharacterStateMachine`이 가지며,
`Dodger` / `Parrier`는 "언제 끝낼지"(타이머)와 "언제 무적/판정 중인지"(창)만 관리한다.

플레이어만 이 두 컴포넌트를 가진다. 적·더미엔 없어도 되고, `Actor`가 `GetComponent`로 찾아 없으면 건너뛴다.

### 회피 (`Dodger`)

- **지상에서만** 시작, 진행 중이던 공격을 캔슬(`fighter.CancelAttack()`).
  점프 준비·공중·피격 여파는 캔슬 불가 (`CanAct`에 `Attack`만 다시 더한 조건).
- 무적은 회피 전체가 아니라 `invulnerableStartDelay` ~ `+ invulnerableDuration` 구간만.
  앞뒤로 취약 프레임이 있다. `Health.OnHit`이 `IsInvulnerable`을 보고 그 프레임 피격을 통째로 무시.
- 시작 시 바라보는 방향으로 대시 = `ApplyKnockback(FacingDir × dashSpeed, dashDeceleration)` (y=0이라 그라운드 슬라이드 경로).
- `OnDodgeSuccess` 이벤트를 뚫어놨다 — 반격·슬로모·게이지 충전 같은 보상을 나중에 여기 구독으로 붙인다.

### 패링 (`Parrier`)

- 자세가 **[시동 → 판정 창 → 후딜]** 세 구간. 판정 창(`IsParryWindowActive`) 안에서 맞아야만 성공,
  시동·후딜에 맞으면 정상 피격.
- 회피와 달리 자기 공격을 캔슬하지 않는다 — 중립/이동에서만 발동.
- **적 스턴은 기존 피격 경로를 재사용한다:** 성공 시 공격자의 `IHittable.OnHit`을 데미지 0짜리
  `HitData`로 호출 → 공격자가 `CancelAttack` + 그라운드 슬라이드(`Stun`) + `Interrupt`를 그대로 받는다.
  `staggerDeceleration`을 일반 피격보다 낮게 둬서 스턴이 더 길다 = 확정 반격 기회.
- `OnParrySuccess` 이벤트로 이펙트·SE·자동 반격을 나중에 붙인다.

## 6. 상태 — `CharacterStateMachine`

`CharacterState` enum **하나로** 논리 게이팅(`CanAct` / `IsMovementLocked`)과 애니메이션
(상태 이름 == 클립 이름으로 CrossFade, 스프라이트 좌우 반전)을 동시에 굴린다.

> 예전엔 `ActionPhase`(논리) + `CharacterState`(표현) 두 개를 두고 매 프레임 "phase → 같은 이름 state"로
> 옮겨 적었는데, 그 번역 사다리를 없앤 것이 통합의 핵심이다.

### 상태는 두 종류

| 종류 | 값 | 전환 방식 |
|---|---|---|
| **물리 파생** | `Idle` `Move` `InAir` `Stun` `Airborne` | `Evaluate()`가 매 프레임 `Locomotion` 상태에서 재계산 (우선순위 `Airborne > Stun > InAir > Move > Idle`) |
| **고정(sticky)** | `JumpStart` `JumpLand` `Attack` `Dodge` `Parry` `ParrySuccess` `Landed` `GetUp` | 명시적 `Enter*` 호출로 진입, 명시적 호출/애니메이션 이벤트로만 탈출. `Evaluate`는 sticky면 조기 반환 |

`Attack` / `Dodge` / `Parry` / `ParrySuccess`는 각자 컴포넌트(`Fighter` / `Dodger` / `Parrier`)의
타이머로 자력 종료한다. `JumpStart` / `JumpLand` / `Landed` / `GetUp`은 **애니메이션 이벤트가 도착해야만**
끝나므로, 이벤트가 빠지면 캐릭터가 영구히 잠긴다 → **워치독**이 `actionPhaseTimeout`(기본 2초) 후
강제 해제하고 콘솔에 "어떤 이벤트를 기다렸는지" 경고를 찍는다.

### 애니메이션은 단방향으로 구동된다

상태머신이 Animator를 몰고, 역방향(Animator 상태를 읽어 로직 판단)은 없다.
Animator에는 Transition 화살표가 하나도 없고, 전환은 전부 코드가 `CrossFade`(또는 하드컷 `Animator.Play`)로 시킨다.
그래서 **Animator State 이름 == `CharacterState` 값 == 공격 클립 이름**이 깨지면 그 상태만 조용히 안 바뀐다
(경고 1회).

## 7. 애니메이션 이벤트 다리 — `AnimationEventRelay`

Animation Event는 Animator가 붙은 바로 그 오브젝트로만 전달된다. 그래서 이 스크립트는 반드시
Animator와 같은 오브젝트(캐릭터의 `Visual` 자식)에 붙고, 받은 이벤트를 부모 계층의 담당 컴포넌트로 중계만 한다.

| 클립 이벤트 | 심는 클립 | 최종 처리 |
|---|---|---|
| `OnAttackHitFrame` | 각 공격 클립 | `Fighter.OnAttackHitFrame` → 히트스캔 |
| `OnJumpLaunchFrame` | JumpStart | `CharacterStateMachine` → `Locomotion.Jump()` (여기서 실제로 뜸) |
| `OnJumpLandEndFrame` | JumpLand | 착지 경직 해제 |
| `OnKnockdownGetUpStartFrame` | Landed | `Landed` → `GetUp` |
| `OnKnockdownGetUpEndFrame` | GetUp | 기상 완료 |

`AttackData.HitFrameEventName`이 `nameof(AnimationEventRelay.OnAttackHitFrame)`으로 묶여 있어,
릴레이 메서드 이름을 바꾸면 컴파일이 깨진다(더 이상 매직 스트링이 아님).

---

## 8. 데이터는 전부 ScriptableObject

로직과 수치를 분리한다. 컴포넌트는 에셋을 참조만 하고, 값은 인스펙터에서 채운다.

| 에셋 | 읽는 곳 | 내용 |
|---|---|---|
| `MovementStatData` | `Locomotion.Awake`가 복사 | 이동 속도·중력 배율·점프력·바운스·공중 판정 임계값 |
| `CharacterStatData` | `Health` | 최대 체력 |
| `GlobalPhysicsData` | `Locomotion.Tick`이 매 프레임 읽음 | 전역 중력. `Resources/`에 이름 `GlobalPhysicsData`로 **1개만** |
| `AttackData` (하위 타입) | `PlayerInput` / `EnemyBrain` → `Fighter` | 데미지·사거리·넉백·쿨타임·클립·콤보 체인·이동 방식 |

캐릭터별 "무게"는 개별 스탯에 중력값을 따로 두지 않고 `GlobalPhysicsData.gravity × MovementStatData.gravityScale`
배율로만 다르게 준다.

## 9. 관리상 지켜야 하는 계약 (깨면 조용히 버그)

| 규칙 | 이유 |
|---|---|
| **Animator State 이름 == `CharacterState` 값 == 공격 클립 이름** | `CrossFade`가 문자열/해시로 매칭, 없으면 조용히 실패 |
| **`AnimationEventRelay`는 Visual 자식(Animator 있는 곳)에** | 애니메이션 이벤트는 Animator의 GameObject로만 전달 |
| **원샷 스프라이트 클립은 Loop Time 끄기, 전환 블렌드 0** | 스프라이트는 프레임 보간 불가 — 이벤트→상태 전환 1프레임 사이에 loop가 되감겨 깜빡임 |
| **캐릭터당 `targetLayer`에 걸리는 콜라이더 1개** | 여러 개면 `OverlapSphere`가 그 수만큼 반환 → `OnHit` 중복 (Fighter가 방어는 함) |
| **몸 컴포넌트는 자기 `Update()`를 두지 않는다** | 실행 순서 의존이 생기면 프레임 순서 버그가 다시 가능해진다 |
| **`Locomotion`은 아무도 직접 호출하지 않는다** (`Jump` 예외) | 이동 로직의 단방향 격리 — 의존 그래프 종점 유지 |
| **`UnityEngine.Object`는 `?.` / `??` 대신 `== null`** | 파괴된 오브젝트의 "fake null" 때문 |
| **8방향 스냅: 플레이어 켬 / AI 끔** | AI는 임의 각도로 목표를 향해야 함 |

## 부록 A: 적 AI (2026-09-09 추가)

`EnemyBrain : IIntentSource`가 몸(`Actor` 이하)은 그대로 두고 판단만 담당한다. 함수 시그니처는
[프로젝트-사전.md §7.5](프로젝트-사전.md), 만든 과정은 [2026-09-09.md](2026-09-09.md).

- **판단은 경량 FSM** — 한 번에 `EnemyBehavior` 하나가 활성. 전환은 `[reset]` 경유(`current`를 직접 안 바꿈).
- **행동 노드는 4단계 위상** — Startup(예비 동작) → Active → Recovery(후딜) → Done. `maxActiveDuration`이
  있어 조건이 안 맞아도 반드시 끝난다.
- **이동은 `EnemyOrbitMovement`** — 대상 주위 궤도. 노드는 각도/반경만 넘기고 "어떻게 가는가"는 이 모듈이.
  속도는 이진법(정지/최고속) — 연속성은 궤도 각도가 프레임에 걸쳐 바뀌는 것으로.
- **행동 선택은 `WeightedBehaviorSelector`** — 확률 가중치 + dry-fire(헛방). 성향은 `EnemyArchetype`[SO]로 가중치만 교체.
- **히트스턴 이탈 → 즉시 재판단** — 얻어맞는 동안 위상 타이머 정지, 벗어난 프레임에 `[reset]` 강제.
- **다수 적은 `SquadController`가 조율** — 개별 브레인 바깥. 포위 슬롯 각도를 블랙보드(`SlotAngle`)에
  써주고, 공격은 토큰으로 교대. 스쿼드 없으면 각 적 솔로.
- **사망** — `CharacterState.Dead`(종착 상태) → `Actor.Update` 정지. 소멸은 `EnemyDespawn`(적 전용, `OnDeath` 구독).

## 부록 B: 아직 안 된 것

- **원거리 공격** — `Fighter`는 근접(`OverlapSphere`) 전용. 투사체 경로는 아직 없음.
- **회피/패링 보상** — `OnDodgeSuccess` / `OnParrySuccess` 훅은 뚫려 있지만 구독자가 콘솔 로그뿐.
- **잡기/던지기** — 지침서가 공용 부모에 두라는 항목. 미구현.
- **궤도 반경 보정 · z축 공격 판정 폭** — 지침서 2·6장. 지금은 `Locomotion` 클램프 / `OverlapSphere` 반경에 의존.
