01

큰 그림

이 프로젝트의 캐릭터는 하나의 큰 스크립트가 아니라, 역할이 나뉜 작은 컴포넌트 여러 개로 되어 있습니다. 오브젝트에 부품을 붙여 조립하는 방식입니다.

캐릭터 한 명 = 부품 조립

사람 한 명을 만든다고 생각하면 이렇게 나뉩니다.

컴포넌트비유하는 일
PlayerInput
(또는 EnemyBrain)		조종하는 사람“오른쪽으로 가고 싶다, 공격하고 싶다”를 말만 함. 직접 움직이지 않음
Actor지휘자매 프레임 “너 먼저, 그다음 너” 순서를 정해줌. 자기는 아무 일도 안 함
Locomotion다리실제로 위치를 옮김. 중력·점프·넉백·벽 충돌 전부 담당
Fighter팔공격을 실행하고 누구를 맞혔는지 판정
Health체력맞으면 피가 깎이고, 하던 동작을 끊음
CharacterStateMachine상태 + 얼굴“지금 뭐 하는 중인지”를 정하고, 그에 맞는 애니메이션을 틀어줌
AnimationEventRelay전화 교환원애니메이션이 “지금이야!” 하고 외치면 안쪽에 전달 (Visual 자식에 붙음)

한 프레임에 일어나는 일

조종하는 사람은 말만 하고, Actor가 순서를 정하고, 다리·팔·상태가 실행한다. 애니메이션은 반대로 “지금이 그 순간”을 알려주는 역할.

여기가 핵심 플레이어와 적은 완전히 같은 몸을 씁니다. 다른 건 “조종하는 사람”뿐이에요 — 플레이어는 PlayerInput(키보드), 적은 나중에 붙일 EnemyBrain(AI). 그래서 적을 만들 때 이동·공격·피격을 새로 짤 필요가 없습니다.
02

컴포넌트 카탈로그

각 컴포넌트가 무슨 일을 하고, 누구와 이야기하고, 인스펙터에서 뭘 채워야 하는지. 고칠 때 어디를 봐야 하는지도 같이 적었습니다.

Actor
지휘자. 매 프레임 다른 컴포넌트들을 정해진 순서로 부릅니다. 자기 자신은 아무것도 계산하지 않습니다.
연결
조종하는 사람(IIntentSource)에게 물어보고 → Fighter, Locomotion, CharacterStateMachine에게 시킴
인스펙터
채울 것 없음. 붙이기만 하면 나머지 4개(Locomotion·Fighter·Health·CharacterStateMachine)가 자동으로 같이 붙습니다
없으면
캐릭터가 완전히 멈춥니다. 아무도 부르는 사람이 없으니까요
고칠 때
“공격 방향이 한 프레임 늦다”, “점프하자마자 착지 판정이 뜬다” 같은 순서 문제는 전부 여기
Locomotion
다리. 위치를 실제로 옮깁니다. 중력, 점프, 넉백, 바닥·벽 충돌, 맵 밖으로 못 나가게 막는 것까지 전부 여기입니다.
연결
아무도 호출하지 않는 종점. Actor가 시키고, Fighter(돌진)와 Health(넉백)가 부탁하지만 Locomotion은 다른 컴포넌트를 부르지 않습니다
인스펙터
  • 이동 스탯 — MovementStatData 에셋 (속도·점프력·중력배율 등)
  • 8방향 스냅 — 플레이어는 켬(키보드는 8방향이 자연스러움), AI는 꺼야 함(임의 각도로 목표를 향해야 하니까)
없으면
Actor가 자동으로 붙여줍니다. 스탯 에셋을 안 넣으면 코드 기본값으로 돌고 경고가 뜹니다
고칠 때
이동이 느리다/빠르다, 점프가 낮다, 넉백이 이상하다, 벽을 뚫는다 → 여기 또는 MovementStatData 에셋
Fighter
팔. 공격을 실행하고, 정해진 순간에 “누가 맞았나”를 검사합니다. 콤보를 다음 단계로 넘기는 것도 여기입니다.
연결
맞은 상대의 Health를 직접 부릅니다(오브젝트를 건너뜀) · Locomotion에게 돌진을 부탁 · CharacterStateMachine에게 “공격 애니메이션 틀어줘”
인스펙터
공격 대상 레이어 — 이 캐릭터가 때릴 대상의 Layer. 플레이어면 Enemy, 적이면 Player. 자기 자신 레이어를 넣으면 자기를 때립니다
없으면
Actor가 자동으로 붙여줍니다
고칠 때
공격이 안 맞는다, 데미지가 이상하다, 콤보가 안 이어진다 → 여기 또는 AttackData 에셋(06번 참고)
Health
체력. 맞으면 피를 깎고, 하던 동작을 무조건 끊습니다. 공격 중이든 점프 중이든 상관없이요.
연결
맞는 순간 Fighter(하던 공격 취소) → Locomotion(넉백) → CharacterStateMachine(상태 끊기) 셋을 차례로 부릅니다
인스펙터
캐릭터 스탯 — CharacterStatData 에셋 (최대 체력)
없으면
Actor가 자동으로 붙여줍니다. 에셋을 안 넣으면 체력 100으로 돌고 경고가 뜹니다
고칠 때
체력을 바꾸려면 에셋을, 죽었을 때 뭘 할지는 OnDeath 이벤트를 구독하는 컴포넌트를 새로 만들면 됩니다 (아직 없음)
CharacterStateMachine
상태 + 얼굴. “지금 서 있나, 걷나, 때리나, 맞고 쓰러졌나”를 하나의 상태로 관리하고, 그에 맞는 애니메이션을 자동으로 틀어줍니다.
연결
Locomotion의 상태를 읽어서 판단 · Animator와 SpriteRenderer를 직접 조작 · Fighter/Health가 “이 상태로 바꿔줘”라고 부름
인스펙터
  • 전환 블렌드 시간 — 0으로 두세요. 스프라이트 애니메이션은 프레임 사이를 섞을 수 없어서, 0이 아니면 두 그림이 번갈아 나오며 깜빡입니다
  • 동작 최대 지속시간 — 안전장치(기본 2초). 애니메이션 이벤트가 안 오면 강제로 풀어주고 경고를 남깁니다. 정상이면 절대 발동하지 않습니다
없으면
Actor가 자동으로 붙여줍니다. Animator를 못 찾으면 경고만 뜨고 게임은 돌아갑니다(애니메이션만 안 나옴)
고칠 때
애니메이션이 안 바뀐다, 이상한 자세로 멈춘다, 깜빡인다 → 여기 + 05번(애니메이션 연결)
PlayerInput — 조종하는 사람 (플레이어용)
키보드를 읽어서 “뭘 하고 싶은지”로 바꿔줍니다. 직접 움직이거나 때리지 않습니다. 적을 만들 땐 이 자리에 EnemyBrain이 들어갑니다.
연결
Actor가 매 프레임 “뭐 할래?”라고 물어봄. 그 외에는 아무와도 이야기하지 않습니다
인스펙터
  • 공격 1 (X키) — 콤보를 시작할 AttackData 에셋
  • 공격 2 (Z키) — 특수공격. 비워두면 Z키는 그냥 무시됩니다
조작
WASD·방향키 이동 / X 공격1 / Z 공격2 / C 점프 — 키 배치는 스크립트 안에 직접 있습니다(별도 에셋 없음)
고칠 때
키를 바꾸려면 PlayerInput.cs의 Awake, 공격을 바꾸려면 인스펙터의 에셋만 교체
AnimationEventRelay — Visual 자식에 붙임
전화 교환원. 애니메이션 클립이 “지금이 때리는 순간!”, “지금 발이 떨어졌어!”라고 외치면 그걸 부모(캐릭터 본체)에게 전달합니다.
연결
부모의 Fighter(타격 순간)와 CharacterStateMachine(점프 발사·기상)에게 전달
위치
반드시 Animator가 붙어 있는 오브젝트(=Visual 자식)에. 루트에 붙이면 작동하지 않습니다 — 애니메이션 이벤트는 Animator가 있는 오브젝트로만 전달되기 때문
인스펙터
채울 것 없음. 부모를 알아서 찾습니다
없으면
콘솔에 "... has no receiver!" 경고. 공격이 아무도 안 맞고, 점프가 안 뜨고, 넘어진 뒤 못 일어납니다(2초 뒤 안전장치가 풀어줌)

덤: 디버그용 3종 (있어도 없어도 게임은 돌아감)

컴포넌트보여주는 것
CharacterStateDebugDisplay머리 위에 현재 상태 + 바라보는 방향 화살표
HealthDebugDisplay머리 위에 현재 / 최대 체력
AttackRangeGizmo씬 뷰에 공격 판정 구체. 회색=대기 흰색=휘두르는 중 빨강=맞히는 순간
03

플레이어 오브젝트 만들기

빈 오브젝트에서 시작해 조작 가능한 플레이어까지. 코드는 한 줄도 안 씁니다 — 오브젝트를 만들고 컴포넌트를 붙이고 에셋을 연결하는 작업뿐입니다.

  1. 빈 오브젝트를 만들고 이름·레이어·태그 정하기

    Hierarchy에서 우클릭 → Create Empty. 이름을 Player로.

    • Layer = Player — 적의 공격이 “누구를 때릴지” 고르는 기준
    • Tag = Player (선택사항, 지금은 안 쓰임)
    • Position = (0, 0.5, 0) — y는 콜라이더 절반 높이만큼. 바닥에 딱 서게 하려고
  2. Collider 붙이기

    Add Component → Box Collider (3D). Size (1, 1, 1), Center (0,0,0), Is Trigger는 끔.

    왜 필요한가 두 가지 역할을 합니다. ① 남의 공격에 맞는 피격 범위가 되고, ② Locomotion이 이 크기를 읽어서 바닥에 서는 높이와 벽에 닿는 반경을 자동 계산합니다. 그래서 Collider 없이는 시작조차 안 됩니다.
    주의 캐릭터당 콜라이더는 하나만. 자식에 또 붙이면 한 번 때렸는데 두 번 맞은 걸로 처리돼서 데미지가 2배가 되고 넉백이 이상해집니다.
  3. Actor 붙이기 — 나머지가 따라옵니다

    Add Component → Actor. 그러면 Locomotion, Fighter, Health, CharacterStateMachine이 자동으로 같이 붙습니다. 하나씩 찾아 붙일 필요 없습니다.

  4. 스탯 에셋 만들어서 연결하기

    Project 창에서 우클릭 → Create → DoitMySelf 메뉴로 두 개를 만듭니다.

    • Movement Stat Data → 이름 PlayerMovementStatData → Locomotion의 이동 스탯에 드래그
    • Character Stat Data → 이름 PlayerStatData → Health의 캐릭터 스탯에 드래그

    Locomotion의 8방향 스냅은 켜둡니다(키보드 조작이라).

  5. 때릴 대상 지정하기

    Fighter의 공격 대상 레이어를 Enemy로. (플레이어는 적을 때리니까요.)

    자주 하는 실수여기를 비워두면 공격이 아무도 안 맞습니다. 자기 레이어를 넣으면 자기를 때립니다.
  6. Visual 자식 만들기 — 그림이 들어가는 곳

    Player 밑에 빈 오브젝트를 하나 만들고 이름을 Visual로. 여기에 붙일 것:

    • Sprite Renderer — 캐릭터 그림
    • Animator — Controller에 PlayerAnimatorController 연결, Apply Root Motion은 끔
    • AnimationEventRelay — 반드시 여기(Animator와 같은 오브젝트)에

    Transform은 Rotation Y = 180, Position은 그림이 콜라이더에 맞게 보이도록 조정 (현재 플레이어는 (0, 1.13, 0)).

    Y를 180도 돌리는 이유 카메라가 z = -10에서 +Z 방향을 바라봅니다. 스프라이트의 앞면은 로컬 +Z라, 그대로 두면 카메라가 뒷면을 보게 됩니다. 180도 돌려야 앞면이 카메라를 향합니다.
  7. 조종할 사람 붙이기

    Player 루트에 PlayerInput을 추가하고, 공격 1 (X키)에 AttackData 에셋을 연결합니다 (공격 만드는 법은 06번).

    공격 2 (Z키)는 비워둬도 됩니다 — 그러면 Z키가 아무 일도 안 합니다.

  8. (선택) 디버그 표시 붙이기

    루트에 CharacterStateDebugDisplay, HealthDebugDisplay, AttackRangeGizmo를 붙이면 상태·체력·공격범위가 눈에 보입니다. 만들면서 확인할 때 아주 유용하고, 나중에 떼기만 하면 됩니다.

  9. 확인

    Play를 눌러서:

    • 바닥에 서 있고 아래로 안 꺼진다
    • WASD/방향키로 8방향 이동, 좌우 반전됨
    • C키로 점프 → 뜨고 → 착지
    • X키로 공격 애니메이션
    • 콘솔에 경고가 하나도 없다
씬에 하나는 있어야 하는 것 맵 오브젝트에 MapBounds 컴포넌트가 붙어 있어야 캐릭터가 맵 밖으로 안 나갑니다(씬에 하나만). 그리고 Assets/.../Resources/ 폴더에 GlobalPhysicsData라는 이름의 에셋이 있어야 중력이 적용됩니다. 둘 다 이미 씬에 있으니 새로 만들 필요는 없습니다.
04

적 오브젝트 만들기

플레이어와 99% 같습니다. 03번을 그대로 하되 아래 다섯 가지만 다르게 하면 됩니다.

항목플레이어적
LayerPlayerEnemy
Fighter · 대상 레이어EnemyPlayer
조종하는 사람PlayerInputEnemyBrain (아직 없음)
Locomotion · 8방향 스냅켬꺼야 함
Animator ControllerPlayerAnimatorControllerEnemyAnimatorController
지금 당장 쓸 수 있는 것 조종하는 사람을 아예 안 붙이면 “훈련용 허수아비”가 됩니다. 가만히 서 있고, 맞으면 정상적으로 넉백·경직·쓰러짐·기상까지 다 합니다. 공격을 만들고 테스트할 때 딱 좋습니다 — 지금 씬의 적이 이 상태입니다.
AI를 붙일 때 잊지 말 것 8방향 스냅을 꺼야 합니다. 켜져 있으면 적이 플레이어를 향해 45도 단위로만 움직여서 어색하게 다가옵니다. (지금 씬의 적은 켜진 상태입니다 — 허수아비라 티가 안 날 뿐입니다.)

적 애니메이션은 더 적어도 됩니다

적이 점프를 안 한다면 JumpStart / JumpLand 상태가 없어도 됩니다. 현재 적 Animator에는 8개만 있습니다: Idle · Move · Attack · InAir · Airborne · Stun · Landed · GetUp.

없는 상태로 바뀌려고 하면 콘솔에 “Animator에 'XXX' State가 없어 애니메이션이 바뀌지 않습니다” 경고가 한 번 뜹니다. 게임은 계속 돌아가고, 이전 애니메이션이 그대로 재생됩니다.

05

애니메이션 연결

이 프로젝트의 Animator는 화살표(Transition)를 하나도 쓰지 않습니다. 상태 전환은 전부 코드가 직접 시킵니다. 그래서 규칙이 아주 단순합니다.

규칙 1 — State 이름을 정확히 맞춘다

CharacterStateMachine은 상태 이름과 똑같은 이름의 Animator State를 찾아서 재생합니다. 이름이 하나라도 다르면 그 상태만 조용히 안 바뀝니다.

State 이름언제 나오나Loop애니메이션 이벤트
Idle가만히 있을 때켬—
Move걸을 때켬—
InAir공중에 떠 있을 때켬—
Stun가볍게 맞고 밀릴 때켬—
Airborne강하게 맞고 떴을 때켬—
JumpStart점프 준비 동작꺼야 함OnJumpLaunchFrame (발 떼는 프레임)
JumpLand착지 경직꺼야 함OnJumpLandEndFrame (마지막 프레임)
Landed넉백으로 쓰러져 있을 때꺼야 함OnKnockdownGetUpStartFrame (마지막)
GetUp일어나는 중꺼야 함OnKnockdownGetUpEndFrame (마지막)
공격 클립 이름
예: Attack 1		공격할 때꺼야 함OnAttackHitFrame (맞히는 프레임)
공격만 규칙이 다릅니다 다른 상태는 상태 이름으로 찾지만, 공격은 클립 이름으로 찾습니다. 콤보 단계마다 다른 그림을 틀어야 하니까요. 그래서 공격은 AttackData에 넣은 클립 이름과 Animator State 이름이 같아야 합니다 (예: 클립이 Attack 1이면 State 이름도 Attack 1).

규칙 2 — 한 번만 재생되는 클립은 Loop를 끈다

이거 하나로 버그가 납니다 애니메이션 이벤트가 발동한 뒤 실제 상태가 바뀌기까지 항상 1프레임이 걸립니다. 그 사이에 Loop가 켜진 클립은 첫 프레임으로 되감깁니다. 그래서 일어나다 말고 다시 눕는 것처럼 한 프레임 깜빡입니다.

JumpStart · JumpLand · Landed · GetUp · 모든 공격 클립은 반드시 Loop Time을 꺼야 합니다.

규칙 3 — 전환 블렌드는 0

스프라이트 애니메이션은 그림 A와 그림 B 사이를 섞을 수 없습니다. CharacterStateMachine의 전환 블렌드 시간이 0보다 크면, 전환하는 동안 두 클립의 프레임이 번갈아 보이며 지저분해집니다. 0으로 두세요.

애니메이션 이벤트 심는 법

  1. 클립 선택 → Animation 창 열기
    Project에서 .anim 클립을 고르고 Window → Animation → Animation.
  2. 원하는 프레임으로 이동 → 이벤트 추가
    타임라인에서 그 프레임에 놓고, 이벤트 추가 버튼(작은 깃발 아이콘)을 누릅니다.
  3. Function 이름을 정확히 입력
    위 표의 이름을 철자 그대로 씁니다. 대소문자도 같아야 합니다.
    파라미터는 비워둡니다.
  4. 확인
    Play해서 콘솔에 has no receiver! 경고가 없으면 연결된 겁니다. 경고가 뜨면 AnimationEventRelay가 Visual에 안 붙어 있는 것입니다.
06

공격 만들기 · 적용 · 수정

공격 하나 = 에셋 파일 하나. 코드를 안 건드리고 인스펙터에서 전부 만들고 조절합니다.

공격은 세 종류가 있습니다

“공격하는 동안 몸이 어떻게 움직이는가”로 나뉩니다. 만들 때 Create 메뉴에서 고릅니다.

종류Create 메뉴공격 중 몸쓰는 곳
LockedAttack Data / Locked제자리 고정, 이동 불가기본 콤보 1타
ImpulseAttack Data / Impulse지정 방향으로 강제 돌진앞으로 파고드는 공격
Allow InputAttack Data / Allow Input공격 중에도 이동 가능 (속도 배율 조절)움직이며 휘두르는 공격

새 공격 만들기

  1. 에셋 만들기
    Project 우클릭 → Create → DoitMySelf → Attack Data → 종류 선택. 이름은 알아보기 쉽게 (AttackData_Locked처럼).
  2. 애니메이션 클립 연결
    공격 애니메이션 클립에 .anim을 넣습니다.
    • 공격이 얼마나 오래 지속되는지는 이 클립 길이에서 자동으로 계산됩니다
    • 클립에 OnAttackHitFrame 이벤트가 있어야 합니다 — 없으면 공격이 아무도 안 맞습니다
    • Animator에 클립 이름과 똑같은 State가 있어야 그림이 나옵니다
    밸런스를 클립과 분리하고 싶다면 지속시간 직접 지정에 0보다 큰 값을 넣으면 클립 길이 대신 그 값을 씁니다. 애니메이터가 클립을 손봐도 전투 밸런스가 안 흔들립니다. 0이면 클립 길이를 씁니다(기본).
  3. 위력과 범위 정하기
    데미지
    깎을 체력
    공격 사거리
    캐릭터 앞으로 얼마나 떨어진 지점을 때리는지
    공격 판정 반경
    그 지점을 중심으로 한 구체의 크기

    씬 뷰에서 AttackRangeGizmo가 이 구체를 그려주니 보면서 조절하면 됩니다.

  4. 넉백 정하기 — 지상용과 공중용이 따로 있습니다

    맞은 상대가 땅에 있냐 떠 있냐에 따라 다른 값이 적용됩니다. 저글링(공중 콤보)을 만들 때 중요합니다.

    필드언제
    밀치는 힘 / 띄우는 힘상대가 땅에 있을 때
    밀치는 힘(공중) / 띄우는 힘(공중)상대가 이미 떠 있을 때
    그라운드 슬라이드 감속안 띄우고 밀기만 할 때 얼마나 빨리 멈추는지
    자주 헷갈리는 것 “띄우는 힘을 올렸는데 공중에서 안 뜬다” → 저글링은 띄우는 힘(공중)을 씁니다. 지상용을 아무리 올려도 첫 타에만 적용됩니다.
    반대로 띄우는 힘을 0으로 하면 안 뜨고 밀리기만 합니다(경직 상태).
  5. 콤보로 잇기

    후속 공격 칸에 다음 AttackData 에셋을 넣으면 콤보가 됩니다.

    공격이 재생되는 동안 같은 키를 또 누르면 클립이 끝나는 순간 다음 공격으로 넘어갑니다. 비워두면 거기서 콤보가 끝납니다.

    현재 플레이어 콤보 AttackData_Locked(Attack 1, 제자리) → AttackData_Impulse(Attack 2, 돌진) → 끝. 2타입니다.
  6. 캐릭터에 연결하기

    만든 에셋을 PlayerInput의 공격 1(또는 공격 2)에 드래그하면 끝입니다. 콤보의 첫 번째 공격만 넣으면 됩니다 — 나머지는 후속 공격을 따라 알아서 이어집니다.

특수공격에 캔슬 권한 주기

다른 공격을 끊고 나갈 수 있음을 켜면, 다른 공격이 재생되는 도중에도 이 공격으로 갈아탈 수 있습니다.

  • 캔슬은 모든 공격의 권리가 아니라 특정 공격만 갖는 특권입니다 (기본은 꺼짐)
  • 상대 공격이 이미 맞히는 순간을 지난 뒤에만 캔슬됩니다 — 안 그러면 계속 갈아타며 한 대도 안 맞는 무한 취소가 됩니다
  • 즉 캔슬 가능 구간 = 맞히는 프레임 ~ 클립 끝. 이 구간을 늘리려면 클립의 OnAttackHitFrame 이벤트를 앞으로 옮기면 됩니다

  3. Animator에 클립 이름과 같은 State를 만든다

08

문제 해결

증상을 클릭하면 원인과 해결이 나옵니다.

공격이 아무도 안 맞는다

원인 후보

  • 클립에 OnAttackHitFrame 이벤트가 없다 — 콘솔에 경고가 뜹니다. 05번대로 이벤트를 심으세요
  • Fighter의 공격 대상 레이어가 비었거나 틀렸다 — 플레이어면 Enemy여야 합니다
  • 맞는 쪽에 Collider가 없다 — 피격 판정은 Collider로 합니다
  • 사거리·반경이 너무 작다 — AttackRangeGizmo로 눈으로 확인하세요
데미지가 2배로 들어간다 / 넉백이 이상하다

원인

맞는 캐릭터에 Collider가 2개 이상입니다. 하나의 공격이 두 번 맞은 걸로 처리되고, 두 번째 호출이 첫 번째의 넉백을 덮어씁니다(그래서 “띄우는 힘이 안 먹는” 것처럼 보입니다).

해결

캐릭터당 대상 레이어에 포함되는 Collider는 하나만 남기세요.

애니메이션이 안 바뀐다 (움직이는데 서 있는 자세)

원인

Animator에 그 이름의 State가 없습니다. 콘솔에 Animator에 'Move' State가 없어... 경고가 한 번 떴을 겁니다.

해결

05번 표의 이름과 철자·대소문자·띄어쓰기까지 똑같이 State를 만드세요. 공격은 클립 이름과 같아야 합니다.

일어나다가 한 프레임 눕는 것처럼 깜빡인다

원인

Landed / GetUp 클립의 Loop Time이 켜져 있습니다. 이벤트가 발동하고 실제 전환까지 1프레임이 걸리는데, 그 사이 클립이 첫 프레임으로 되감기기 때문입니다.

해결

해당 클립을 선택하고 Inspector에서 Loop Time 체크 해제. CharacterStateMachine의 전환 블렌드 시간도 0인지 확인하세요.

콘솔에 "has no receiver!" 경고가 뜬다

원인

애니메이션 이벤트를 받을 AnimationEventRelay가 없습니다.

해결

Animator가 붙어 있는 오브젝트(Visual 자식)에 AnimationEventRelay를 추가하세요. 루트에 붙이면 안 됩니다 — 애니메이션 이벤트는 Animator가 있는 오브젝트로만 전달됩니다.

"~ 상태가 2초 동안 끝나지 않아 강제로 해제합니다" 경고

이게 무슨 뜻인가

안전장치가 발동한 것입니다. 점프·착지·쓰러짐·기상은 애니메이션 이벤트가 도착해야만 끝나는데, 그 이벤트가 안 와서 캐릭터가 영영 잠길 뻔한 걸 강제로 풀어준 것입니다.

해결

경고 메시지가 어떤 이벤트를 기다렸는지 알려줍니다. 그 이름의 이벤트가 해당 클립에 심어져 있는지 확인하세요. 정상 상태에서는 절대 뜨면 안 되는 경고입니다.

맞았는데 그 뒤로 움직이지 않는다

확인

구조상 잘 안 나는 문제입니다 — 피격은 어떤 동작 중이든 무조건 끊게 되어 있습니다. 그래도 난다면 위의 2초 경고가 같이 떴는지 보세요. 애니메이션 이벤트 누락일 가능성이 큽니다.

캐릭터가 바닥 아래로 꺼지거나 공중에 뜬 채 시작한다

원인

Collider 크기와 시작 위치가 안 맞습니다. Locomotion은 Collider의 절반 높이만큼 위에서 멈추도록 계산합니다.

해결

Collider가 1×1×1이면 시작 y를 0.5로. 크기를 바꿨다면 y도 절반 높이로 맞추세요. (높은 데서 시작해도 그냥 떨어져서 착지하니 큰 문제는 아닙니다)

스프라이트가 뒤집혀 보이거나 안 보인다

원인

Visual의 Rotation Y가 180이 아닙니다. 카메라가 +Z를 바라보는데 스프라이트 앞면도 +Z라, 돌리지 않으면 뒷면이 보입니다.

해결

Visual의 Rotation을 (0, 180, 0)으로.

공격 판정이 그림과 다른 곳에서 나간다

원인

판정은 루트 오브젝트 위치 기준인데, Visual의 Position이 옆으로 밀려 있으면 그림만 어긋나 보입니다.

해결

Visual의 Position x는 0으로 두고 y만 조절해서 그림을 콜라이더에 맞추세요. (현재 씬의 적은 x = −1로 밀려 있습니다)

Play 중이 아닐 때 공격 범위 기즈모가 안 보인다

정상입니다

공격 범위는 지금 실행 중인 공격에서 읽어오는데, Play 전에는 그게 없어서 반경 0으로 그려집니다. Play를 눌러 공격해보면 보입니다.
