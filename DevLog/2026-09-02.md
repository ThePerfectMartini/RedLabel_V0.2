상속이 아니라 **역할별 MonoBehaviour를 오브젝트에 붙여 조립하는 방식**으로 한 번에 정리했다.

## 배경

- `1c63fc0`("적 AI 브레인 계층 + 스탯 에셋 전부 제거 — 백지 초기화")를 기점으로 `develop-v2` 브랜치를 파고 그 위에서 작업.
- 적 AI를 새로 만들기 전에 "몸" 쪽 구조부터 갈아엎기로 함. 이번 범위는 **스켈레톤 + 플레이어**, 적 AI 판단 로직은 이후.

## 결정 (작업 전)

| 갈래 | 선택 | 이유 |
|---|---|---|
| 코어 형태 | 순수 C#이 아니라 **MonoBehaviour 컴포넌트** | 인스펙터에서 붙여 조립. 유닛 테스트는 우선순위 아님 |
| 컨트롤러 범위 | **캐릭터 전용** | player/enemy가 하나의 Actor 공유, intent source만 교체 |
| 기존 액션 로직 | **최소 재구축** (충실 이식 아님) | 콤보/캔슬/점프/넉다운/워치독을 필요한 만큼만 다시 |
| 물리 | 커스텀 수동 적분 유지 | 튜닝된 벨트스크롤 감각·바운스·넉백 슬라이드 보존 |

> "코어를 MonoBehaviour에서 떼어낸 것"([2026-08-26.md](2026-08-26.md) 유지 목록 1번)을 이번에 **의도적으로 되돌렸다.**
> 스프라이트 게임 규모에서 순수 C# + 래퍼 2계층은 코드만 늘고, 실제로 테스트를 안 쓰고 있었다.

## 컴포넌트 세트

전부 캐릭터 루트에 붙는다. `Actor`의 `[RequireComponent]`가 나머지를 자동 동반.

| 컴포넌트 | 역할 | 대체한 것 |
|---|---|---|
| `Actor` | 유일한 `Update()`. 매 프레임 순서를 한 곳에 고정 | CharacterControllerBase의 Update 루프 |
| `Locomotion` | 이동/중력/점프/넉백/바운스/맵경계/8방향/방향 | MovementCore |
| `Fighter` | 공격 실행 + 콤보/캔슬/버퍼링 + 히트스캔 | CombatCore + Base의 콤보 로직 |
| `Health` | 체력 + 피격 시 상태 중단 지시 | Base의 OnHit / currentHealth |
| `CharacterStateMachine` | 상태 enum 하나로 논리 게이팅 + 애니메이션 CrossFade + 스프라이트 반전 + 워치독 | CharacterStateMachine(구) + CharacterAnimatorBridge + ActionPhase |
| `AnimationEventRelay` | 클립 이벤트 5개를 루트로 중계 (Visual 자식) | 리시버 3개 |
| `PlayerInput` | 키 입력 → CharacterIntent | PlayerController |
| `IIntentSource` | 판단 주체 이음매 | IEnemyBrain (일반화) |

**삭제된 인터페이스:** IStateMachineOwner, IAttackClipSource, IAttackEventListener, IJumpEventListener,
IKnockdownEventListener — "항상 같이 붙는 컴포넌트끼리의 결합을 없애려던" 것들이라, 캐릭터 전용으로
확정한 순간 존재 이유가 사라짐. IHittable(공격자 ≠ 대상)과 IAttackRangeDebugInfo(디버그 툴용)는 유지.

**상태 통합:** ActionPhase(6) + CharacterState(10) → `CharacterState` 하나(10개). 값 개수는 같지만
"phase → 같은 이름 state" 10단 번역 사다리가 사라짐. 고정 상태(JumpStart/JumpLand/Attack/Landed/GetUp) vs
물리 파생 상태(Idle/Move/InAir/Stun/Airborne)로 나뉘고, `Evaluate()`는 고정 상태면 조기 반환 →
Impulse 돌진 슬라이드가 Stun으로 오표시되는 옛 버그가 구조적으로 불가능.

**Actor 프레임 순서 (핵심):**
의도 → **방향 설정(공격 시작 전 잠금 기준)** → 공격 → 점프 → 이동(공격/점프 반영 후 잠금 기준) →
Tick → 착지 엣지 감지 → Fighter.Tick → Evaluate.
방향은 공격 전, 이동은 공격 후 — "→+X 동시 입력 시 오른쪽으로 공격"이 이 순서에서 나온다.

**각 컴포넌트에 Update() 없음:** 상태 변화는 Actor.Update / AnimationEventRelay / 다른 Actor의 공격,
셋 중 하나로만. 실행 순서 의존이 없어 `[DefaultExecutionOrder]` 불필요.

## 검증 중 잡은 버그

### 1. 에디트 모드 NRE — `Fighter.IsAttacking`

`AttackRangeGizmo.OnDrawGizmos`는 플레이 중이 아닐 때도 돈다. 그때는 `Awake` 전이라
`Fighter.stateMachine` / `locomotion`이 null. 구 CombatCore는 `new`로 만든 필드라 이 문제가 없었다.
→ IAttackRangeDebugInfo 표면 프로퍼티(IsAttacking, FacingDir)에 null 가드.
에디트 모드에선 반경 0으로 그려짐(구버전은 필드 기본값 1.5가 보였음).

### 2. AnimationEvent "no receiver" — 적 더미

애니메이션 이벤트는 **Animator가 붙은 그 GameObject로만** 전달된다. `AnimationEventRelay`를
Player Visual엔 붙였는데 더미 Visual엔 안 붙임. 더미는 점프/공격을 안 하니 유일하게 재생되는
이벤트 클립이 Landed/GetUp뿐 → 그것만 경고가 떴다("jump가 특별해서"가 아니라).
→ 캐릭터마다 Visual에 relay 하나. 규칙으로 못박음.

### 3. Land → GetUp 1프레임 깜빡임

두 겹이었다:

- **스프라이트 교체 애니메이션은 프레임 사이 보간 불가.** `transitionDuration = 0.1` 기본값이
  전환 구간에 두 클립 프레임을 번갈아 보여줌. 구 CharacterAnimatorBridge는 씬에서 0으로
  세팅돼 있었음(같은 이유). → 기본값 0으로. + 블렌드 0일 땐 `CrossFadeInFixedTime(_, 0)` 대신
  `Animator.Play`로 하드컷(1프레임짜리 전환 상태를 안 남김).
- **Landed/GetUp 클립이 loop.** 애니메이션 이벤트 발동과 실제 상태 전환 사이엔 항상 1 Animator
  프레임 지연이 있는데, 그 사이 loop 클립이 0프레임으로 되감겨 "누운 첫 프레임"이 튀어나옴.
  → 이 클립들 Loop Time 해제(원샷 애니메이션이라 원래 잘못된 설정. 멈춤 방지는 워치독이 담당).

### 4. 한 타격에 OnHit 2번 — 데미지·넉백 이중 적용

적이 콜라이더 2개(루트 BoxCollider + "Collider" 자식). `Physics.OverlapSphere`가 둘 다 반환 →
`foreach`에서 `OnHit`이 한 프레임에 2번 호출.

- 데미지가 2배로 조용히 들어가고 있었음(Stun/넉다운 테스트가 정상으로 보인 이유: 두 호출이 같은 넉백을 써서).
- **띄우는 힘이 안 먹는 것처럼 보이던 진짜 원인:** 1번째 호출로 대상이 뜨면 `IsGrounded = false` →
  2번째 호출이 `띄우는 힘(공중)`(작은 값)을 골라 `velocity.y`를 덮어씀.

→ `Fighter.PerformHitScan`에 `HashSet<IHittable>`로 스캔당 중복 타격 차단.
(구 CombatCore도 같은 버그가 있었음 — 씬 구성상 안 드러났을 뿐.)
콜라이더는 대상당 1개가 정석 — 더미의 자식 콜라이더는 별도 정리 권장.

## 계획 대비 변경

- **PlayerInput:** 생성된 `PlayerInputAction` 래퍼 대신 코드로 직접 바인딩(Unity 재생성 단계 회피).
  입력 에셋 3개(`PlayerInputAction.*`, `Input/PlayerControls.inputactions`) 삭제. 마우스 좌클릭 공격도 드롭.
- **Data/AttackData:** `ApplySelfMovement` 파라미터 타입 `MovementCore` → `Locomotion`
  (시그니처상 불가피, 로직 무변경).
- **콤보 3타 → 2타:** `AttackData_AllowInput` 삭제, `AttackData_Locked` → `AttackData_Impulse`만.
  `Attack 3.anim` + Animator "Attack 3" 상태는 참조 없는 고아로 남음(나중에 3타 살릴 때 재사용).
- **Z 특수공격:** 전용 클립이 없어 미검증(`PlayerInput.attack2Data` 비워두면 무시).
- **적 스탯:** 백지 초기화 때 삭제됐던 걸 더미용으로 `Assets/Script/Enemy/Stat/`에 새로 생성.

## 유지할 것

[2026-08-27.md](2026-08-27.md) 유지 목록에서 이번에도 지킨 것:

- **Intent 패턴** (`IIntentSource` → `CharacterIntent` → Actor) — 조종 주체와 몸의 분리
- **AttackData 다형성** (`AllowsPlayerMovement` / `MoveSpeedMultiplier` / `ApplySelfMovement`)
- **HitData가 지상/공중 넉백을 둘 다 싣고 피격자가 고름**
- **입력 시점 / 판정 시점 분리** (`TryAttack` / `OnAttackHitFrame`)
- **애니메이션 단방향 의존** (상태머신이 Animator를 구동, 역방향 없음)
- **배타적 상태는 enum** (`CharacterState`, `Locomotion.AirborneOrigin`)
- **워치독 + 에셋 검증** — 실패를 조용히 두지 않고 원인까지 찍음
- **주석에 "왜" + 실제 겪은 버그 기록**

새로 못박은 규칙:

- 인터페이스는 "항상 같이 붙는 컴포넌트 결합 제거"용으로 만들지 말고, "어디 붙을지 모르는 것"
  (디버그 툴·크로스 오브젝트)에만.
- 캐릭터 Visual 자식에 `AnimationEventRelay` 필수.
- 스프라이트 애니메이션 클립: 원샷은 Loop Time 끄기, 전환 블렌드 0.
